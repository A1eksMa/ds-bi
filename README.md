# ds-bi

Инструмент разработчика: библиотека сохранённых SQL-запросов к базе данных
[`ds`](https://github.com/A1eksMa/ds) с параметрами и группировкой по папкам — чтобы не
набирать один и тот же запрос заново, когда меняется только id или имя источника.

Независимый репозиторий — не встраивается ни в `ds`, ни в `ds-loader`, ни в `ds-sandbox`.
Единственная связь с `ds` — путь к его `data.db`, который указывается параметром; физическое
расположение `ds-bi` относительно других репозиториев не имеет значения.

**Это инструмент разработчика, не продакшен-сервис**: соединение с БД открывается без
ограничений на чтение/запись — можно и нужно руками поправить что-то в `data.db`, если
понадобится. Ответственность за корректность запросов (включая обход собственной
event-sourcing-логики `ds` при прямом `UPDATE`/`DELETE`) — на том, кто пишет `.sql`-файл.

## Требования

Как и у `ds`/`ds-loader`: только стандартная библиотека Python (`>= 3.9`), никаких внешних
зависимостей.

## Быстрый старт

```bash
pip install -e .

# интерактивная навигация по queries/ (без аргументов)
ds-bi --db /path/to/data.db

# одной строкой: путь к запросу + все параметры сразу
ds-bi --db /path/to/data.db catalog/sources
ds-bi --db /path/to/data.db transactions/by_source txn_table=transactions source_name=CRM row_limit=20

# экспорт в файл для Excel
ds-bi --db /path/to/data.db catalog/sources --format csv --out sources.csv
```

Без установки: `PYTHONPATH=/path/to/ds-bi python3 -m src.cli --db ... ...`.

`--db`/`--queries-dir` можно не указывать каждый раз — переменные окружения `DS_BI_DB` /
`DS_BI_QUERIES_DIR` служат дефолтами (сам флаг, если передан, важнее переменной).

## Как хранятся запросы

Обычные `.sql`-файлы в дереве папок под `queries/` (любая вложенность — раскладывай, как
удобно для навигации):

```
queries/
├── ping.sql
├── catalog/
│   ├── sources.sql
│   └── labels_by_source.sql
└── transactions/
    └── by_source.sql
```

Запрос адресуется путём относительно `queries/` с `/` как разделителем, с расширением
`.sql` или без — `transactions/by_source` и `transactions/by_source.sql` эквивалентны.

Шапка файла — две опциональные строки-комментария для навигации и списков:

```sql
-- НАЗВАНИЕ: Последние транзакции по источнику
-- ОПИСАНИЕ: {txn_table} -- "transactions"/"transactions_archive"; :source_name; :row_limit
SELECT ...
```

Без `-- НАЗВАНИЕ:` в качестве заголовка используется имя файла; без `-- ОПИСАНИЕ:` —
«Описание отсутствует». Оба необязательны, но при разрастании `queries/` сильно облегчают
навигацию — см. примеры в `queries/`.

## Параметры в запросе

Два независимых механизма, отличаются синтаксисом:

| Синтаксис | Для чего | Как подставляется |
|---|---|---|
| `:name` | **значения** — числа, строки, даты в `WHERE`/`VALUES` и т.п. | именованный биндинг `sqlite3` — безопасно от SQL-инъекции штатными средствами драйвера |
| `{name}` | **идентификаторы** — имена таблиц/колонок (их нельзя параметризовать биндингом) | текстовая подстановка после проверки по белому списку `^[a-zA-Z0-9_]+$` |

Оба типа можно передать в одной команде:

```bash
ds-bi --db data.db transactions/by_source txn_table=transactions source_name=CRM row_limit=20
```

Любой параметр, не переданный `имя=значение` в командной строке, запрашивается `input()`
по месту — можно передать часть параметров в команде, а остальное ввести по запросу.
Значения `:param` приводятся к числу автоматически, если это возможно (`int` → `float` →
строка как есть); для `{param}` приведение не нужно — там всегда имя, строка.

## Навигация без запоминания путей

Запусти `ds-bi --db data.db` без имени запроса — пронумерованный список текущей папки
(подпапки — с количеством запросов внутри, файлы — с названием и описанием). Дальше:

- номер — спуститься в подпапку или выбрать файл;
- `..` — подняться на уровень выше;
- путь целиком (`crm/revenue/top`) — сразу перейти к файлу в любом месте дерева, не листая;
- пустой ввод / `q` — выйти.

## Формат вывода

`--format table` (по умолчанию, ASCII-таблица в терминал) / `json` / `csv`. Без `--out` —
печатается в stdout; с `--out PATH` — пишется в файл (сообщение об этом — всё равно в
stdout). CSV для `--out` всегда в `utf-8-sig` (с BOM) — иначе Excel на Windows показывает
кириллицу как мусор.
