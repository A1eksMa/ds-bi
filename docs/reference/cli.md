# CLI `ds-bi`

Точка входа — `src/cli.py :: main` (`pyproject.toml` → `[project.scripts] ds-bi`). Только
`argparse`, stdlib.

```
ds-bi [--db PATH] [--queries-dir DIR] [--format {table,json,csv}] [--out PATH]
      [query] [имя=значение ...]
```

| Аргумент | Значение |
|---|---|
| `--db PATH` | путь к `data.db`. По умолчанию — `$DS_BI_DB`, иначе `data.db` (относительно текущей директории). Файл должен существовать — иначе явная ошибка (код `1`), а не тихое создание новой пустой БД (так по умолчанию делает `sqlite3.connect` на несуществующий путь). |
| `--queries-dir DIR` | корень дерева запросов. По умолчанию — `$DS_BI_QUERIES_DIR`, иначе `queries`. Создаётся автоматически, если не существует. |
| `--format {table,json,csv}` | формат результата. По умолчанию `table`. |
| `--out PATH` | записать результат в файл вместо вывода в терминал (сообщение об этом — всё равно в stdout). |
| `query` | путь к запросу в `queries_dir` (например `crm/revenue/top`), с `.sql` или без. Опущен → интерактивная навигация по папкам. |
| `имя=значение ...` | параметры запроса (и `:name`, и `{name}` — одним и тем же синтаксисом в командной строке, система подстановки различает их уже внутри текста запроса, см. [`query-files.md`](query-files.md)). Любой параметр, не переданный здесь, запрашивается `input()` по месту. |

## Коды возврата

- `0` — запрос выполнен (включая `INSERT`/`UPDATE`/DDL без возвращаемых строк).
- `1` — файл `--db` не существует, запрос не найден, недопустимое имя для `{identifier}`,
  ошибка SQL при выполнении, или навигация прервана без выбора (пустой ввод / `q` / пустая
  `queries_dir`).
- `2` — `argparse` не разобрал аргументы.

## Переменные окружения

`DS_BI_DB` / `DS_BI_QUERIES_DIR` — дефолты для `--db`/`--queries-dir`, если флаг не передан
явно (флаг важнее переменной). Полезно, чтобы не повторять путь к `data.db` в каждой
команде — выставить один раз в сессии терминала:

```bash
export DS_BI_DB=/path/to/data.db
ds-bi catalog/sources
ds-bi transactions/by_source txn_table=transactions source_name=CRM row_limit=20
```

## Вывод

Без `--out` — результат печатается в stdout в выбранном `--format`: `table` — ASCII-таблица
(точный исходный рендер из прототипа), `json` — список объектов `{колонка: значение}`
(`ensure_ascii=False`, кириллица не экранируется), `csv` — через стандартный `csv.writer`
(`NULL` → пустая ячейка, а не строка `"None"`).

С `--out PATH` — то же самое пишется в файл. `csv` при этом — всегда в кодировке
`utf-8-sig` (с BOM): без него Excel на Windows определяет кодировку CSV неверно и кириллица
превращается в мусор.

Запрос без возвращаемых строк (`INSERT`/`UPDATE`/DDL) печатает
`[ Запрос успешно выполнен, данные не возвращены ]` и не создаёт файл, даже если задан
`--out` — рендерить нечего.

## Безопасность — намеренно НЕТ ограничений на запись

Это инструмент разработчика, не сервис. Соединение с `data.db` открывается на чтение и
запись без ограничений — `.sql`-файл может и `UPDATE`/`DELETE` что угодно в БД `ds`, в том
числе в обход его собственной event-sourcing-модели (`transactions`/`transactions_archive`
как append-only журнал). Ответственность за то, что делает конкретный `.sql`-файл — на том,
кто его написал и/или запустил.
