# Формат файлов запросов

Источник: `src/discovery.py`, `src/params.py`.

## Расположение и адресация

Любой `.sql`-файл под `queries_dir` (по умолчанию `./queries`, см.
[`cli.md`](cli.md)), на любом уровне вложенности:

```
queries/
├── ping.sql
└── crm/
    └── revenue/
        └── top.sql
```

Адресуется путём относительно `queries_dir` с `/` как разделителем (не `os.sep` —
стабильно между Linux/Windows), с расширением `.sql` или без:

- `crm/revenue/top` и `crm/revenue/top.sql` — одно и то же;
- ведущие/замыкающие `/` игнорируются;
- `..`, `.`, пустые сегменты (двойной `/`) — отклоняются (`FileNotFoundError`), в том
  числе как защита от выхода за пределы `queries_dir` через путь из командной строки.

## Шапка: название и описание

Две опциональные строки-комментария в любом месте файла (обычно — в начале):

```sql
-- НАЗВАНИЕ: Короткое название для списков
-- ОПИСАНИЕ: Что делает запрос и какие параметры ожидает
SELECT ...
```

Регэкспы: `--\s*НАЗВАНИЕ:\s*(.*)` / `--\s*ОПИСАНИЕ:\s*(.*)`, по первому совпадению. Без
`НАЗВАНИЕ:` заголовком становится имя файла (без `.sql`, без пути — просто базовое имя);
без `ОПИСАНИЕ:` — «Описание отсутствует». Оба используются и в интерактивной навигации, и
в сообщении "Результат запроса '<НАЗВАНИЕ>'" при выполнении.

## Параметры

Два независимых механизма — см. `src/params.py`, не путать между собой:

### `:name` — значения

Обычный именованный параметр `sqlite3`. Текст `:name` остаётся в SQL как есть; значение
передаётся драйверу отдельно (`cursor.execute(sql, {"name": value})`) — безопасно от
SQL-инъекции штатными средствами драйвера, годится для чисел/строк/дат в `WHERE`, `VALUES`
и т.п.

Собираются через `bound_params(sql)` — все `:identifier` в тексте, по алфавиту, без
повторов. Значение, введённое строкой (из `имя=значение` в CLI или из `input()`),
приводится к числу через `cast_value`: сначала пробуется `int`, затем `float`, иначе —
остаётся строкой. `int("-5")` отрабатывает корректно (в отличие от наивной проверки через
`str.isdigit()`, которая для отрицательных чисел вернула бы `False`).

### `{name}` — идентификаторы

Имя таблицы или колонки нельзя параметризовать биндингом драйвера (`sqlite3`, как и
большинство SQL-движков, не умеет биндить идентификаторы — только значения). Поэтому
`{name}` подставляется текстом, но только после проверки значения по белому списку
`^[a-zA-Z0-9_]+$` (`validate_identifier`) — иначе `ValueError`, запрос не выполняется.

Собираются через `dynamic_fields(sql)` — по первому появлению, без повторов. Подстановка
(`substitute_identifiers`) делается точечной регэксп-заменой **только** совпадений с
`\{[a-zA-Z0-9_]+\}` — не через `str.format()`. Это принципиально: `str.format()`
интерпретировал бы вообще любые `{...}` в тексте, включая случайный JSON-литерал в самом
запросе (`'{"a": 1}'`), и либо упал бы, либо исказил его. Нашей регэксп-заменой такие
места остаются нетронутыми.

## Пример с обоими механизмами сразу

```sql
-- НАЗВАНИЕ: Последние транзакции по источнику
-- ОПИСАНИЕ: {txn_table} -- "transactions"/"transactions_archive"; :source_name; :row_limit
SELECT t.cnt, s.name AS source, l.name AS label, i.value AS entity_id, v.value AS value
FROM {txn_table} t
JOIN srcs s ON s.src_id = t.src
JOIN lbs  l ON l.lb_id  = t.lb
JOIN ids  i ON i.id_id  = t.id
LEFT JOIN vals v ON v.val_id = t.val
WHERE s.name = :source_name
ORDER BY t.dt DESC
LIMIT :row_limit;
```

```bash
ds-bi --db data.db transactions/by_source txn_table=transactions source_name=CRM row_limit=20
```

Больше примеров — в `queries/` этого репозитория (на реальной схеме `ds`, см. `ds`'s
[`docs/reference/storage-port.md`](https://github.com/A1eksMa/ds/blob/main/docs/reference/storage-port.md)
для списка таблиц).
